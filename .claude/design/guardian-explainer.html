Design spec · issue #309 · target: ICLR

A sentinel that remembers.

The Guardian watches one repository evolve, cycle after cycle, and writes back a cross-cycle memory. It never edits the code — its move is to form a hypothesis about an emerging risk and write a test that exposes it, run it in a throwaway sandbox, and report the evidence. The whole project asks one question.

H1 · does memory beat memoryless — at matched cost? first target · CodeMiner itself 1× H100 80GB · local vLLM · litellm one ephemeral container / cycle non-modifying · zero patches
The idea

Two ways of seeing a repository

The Guardian perceives its target through two facets. The first is standard; the second is the bet.

Facet 1 · current state

The repo right now

CodeMiner's index and compiler-precise code graph at commit t. This is what any single-snapshot tool already sees.

Facet 2 · evolution over time

The repo's history — the memory

What changed across cycles: symbol lifetimes, dependency drift, prior findings, test trajectories. This is the facet a memoryless agent cannot see — and the one under test.

H1 — the whole result

Replaying a repo through its own history, a Guardian arm that carries memory surfaces higher-precision / earlier maintenance findings than an identical memoryless arm, at a bounded per-cycle cost. The headline is Δ, measured — a null or negative result is still a valid answer.

The loop

One cycle, seven steps

Each cycle runs on one commit. Steps 1–3 and 7 are deterministic — no model. Only reflect and investigate call the LLM, which is exactly what lets the memoryless ablation be a clean toggle on what step 4 may read.

◆ the memory layer — the storage & retrieval thread

Repository memory

An append-only store, keyed by commit. It's what makes “memory helps” measurable — and it has to stay cheap to read as history grows, or the memory arm just costs more without winning. Backend is deliberately boring to start; a vector/graph DB is a month-2 decision.

The signal the memory unlocks

Graph-diff drift

Diff the current CodeGraph against the prior snapshot for new/removed edges on high-fan-in symbols, fan-in spikes, and public-API arity/signature changes with lagging dependents. It runs deterministically and emits a plain-English shortlist — only that prose plus retrieved code reaches the model. Its job is selection at repo scale, and it's the sharpest test of H1: structural drift across files is exactly what a single-snapshot arm can't see.

example shortlist  →  parse_config changed arity; 47 dependents; 3 not updated.
The defining action

A risk is confirmed by a test, not an argument

The agent writes a new targeted test whose failure demonstrates the risk, runs it with the repo's own pytest on a throwaway overlay, and corroborates it. Cheaper first-pass probes (existing-test run, call-site grep, import/typecheck) gate the expensive ones. Everything is bounded by a per-cycle budget.

01 · gather

Evidence

HybridRetrievePipeline.query → rows + source spans.

02 · synthesize

Risk-revealing test

Calls the API the way the 47 dependents still do; asserts old behaviour. fails on t = evidence

03 · corroborate

Differential + fix-probe

Passes on t−1, fails now PASS→FAIL · reverting the cause goes green FAIL→PASS

04 · record

Finding

Verdict + reasoning trace + synthesized test + any fix-diff — as evidence, never “apply this.”

Non-modifying invariant · hard constraint

The agent works only inside a per-cycle container on a disposable overlay checkout. Synthesized tests and fix-edits live on the throwaway layer and die with the container. report.py asserts a no-patch invariant; that test stays green. This is what makes “non-modifying” structural, not a promise.

Runtime

One ephemeral container per cycle

Dispatch

Throwaway checkout, overlay mount

git worktree materializes commit t cheaply; a pinned guardian-runtime image mounts /repo as an overlay — worktree = read-only lower, tmpfs upper absorbs edits and is the evidence-diff. Podman (rootless) with Docker fallback; --network none + one localhost rule to the model server; no GPU in the container.

Model server

Local vLLM behind litellm

Qwen3-Coder-Next — 80B-total / 3B-active MoE, 256K context, ~40 GB in 4-bit → KV headroom on one H100. OpenAI-compatible, so nothing in the Guardian changes but the api_base. Cost is enforced by --budget-tokens, paged memory reads, and prompt caching; tokens + wall-clock land in the cycles table.

Evaluation

Future-history replay — and one clean ablation

Run the Guardian as if living through the repo's past, knowledge bounded at each cycle's commit, and check whether its unprompted findings anticipated what actually happened later. Ground truth = post-t issues / bug-fix PRs / reverts, mapped to the symbols they touched (reusing gt_locate.py + eval/retrieval_eval.py).

Metrics

What gets reported

  • precision · recall@horizon · lead-timehow much, how complete, and how early the findings are.
  • memory-unique findingsconfirmed findings memory produced that memoryless didn't — the direct H1 evidence.
  • costtokens + wall-clock, reported at matched budget.
  • non-modifying invariant100% of reports carry zero applied diffs.
Threats to validity

Named up front

  • hindsight leakagenothing after t reaches the sandbox or index — audited.
  • ground-truth incompletenessrecall is a lower bound (not every future fix is captured).
  • n = 1 repo · LLM nondeterminismdirectional at one repo; fixed decoding + model-free signals.
  • invalid synthesized teststhe differential run separates “risk is real” from “test is broken.”

◆ where you fit

Own the memory layer as a research thread

W2 isn't plumbing under the paper — it's the mechanism the result depends on. If memory reads are naive, the memory arm just costs more without winning, and H1 has no signal. Design it well, and “memory helps at matched cost” becomes true. Three knobs, all yours, all publishable:

storage

Versioned, delta-first

store graph snapshots + findings as deltas, not full copies — incremental view maintenance, directly.

retrieval

Budget-bounded reads

page / summarize a growing history into the model's context under a token budget. The actual research question.

cost

The cost axis

you own the cycles table → you own the “quality at a cost” number the headline is reported against.

The open slot — why this is publishable

Nothing verified in this pass combines (a) persistent cross-cycle memory, (b) compiler-precise per-commit graph snapshots, and (c) test synthesis for emerging risk — under a matched-cost ablation. SWE-Bench-CL, SWE-Exp, and SWE-CI each cover one axis; TEBench / TestExplora cover the test axis without memory. That intersection is the ICLR slot the Guardian targets — and the memory layer (your thread) is the axis that makes it hold.
