# CodeNib 0.2.6

CodeNib 0.2.6 adds the change guard. Before Claude Code or Codex says a task is
done, the guard lists the tests the change reaches and the call path to each
one, and shows the notes recorded about the changed code. It runs on your
machine and calls no model.

Install it in a repository:

```bash
python -m pip install --upgrade "codenib[graph]==0.2.6"
cd /path/to/repository
codenib guard install --agent claude      # or --agent codex, or --agent all
```

## Tests at risk, before the agent is done

`codenib guard check` compares the working tree with a commit. It maps each
changed line to the function around it, finds the tests that reach those
functions in at most three calls, and prints each test with its path:

```text
Tests at risk: 3 of 11,144, within 3 calls of the change
  sympy/combinatorics/tests/test_homomorphisms.py::test_check_homomorphism
      test_check_homomorphism (sympy/combinatorics/tests/test_homomorphisms.py:109) -> homomorphism (sympy/combinatorics/homomorphisms.py:306) -> _check_homomorphism (sympy/combinatorics/homomorphisms.py:350) -> _check_homomorphism._image
```

The graph comes from the commit's tracked files, not from your edits, and is
kept for later runs. Calls include constructors: `Cart(...)` reaches
`Cart.__init__`, also through an alias or a base class.

`codenib guard install` adds two hooks. At session start the guard records the
commit the session began from. When the agent is about to finish, the guard
hands back the tests its change reaches and the command that runs them, and the
agent keeps working. It reports each change once and never fails the agent's
turn. Codex runs a new hook after you trust it in `/hooks`.

## Notes that stay attached to code

`codenib guard note add` records a decision, gotcha, invariant or contract as
a Markdown file in `.codenib/notes/`, anchored to the functions it is about. A
change that touches those functions shows the note to the agent; a change to
the anchored code marks the note as possibly out of date until someone confirms
it with `codenib guard note confirm`.

## How well it works

On 68 agent patches that pass SWE-bench Verified's tests but break other tests
in the project's full suite, the guard listed a broken test for 35. On patches
that broke nothing, it listed a median of 3 tests. Selecting every test file
that imports a changed module caught 22, at a median of 81 tests. Most misses
go through calls a code graph cannot see: framework calls by name, operators
and tests that start the program in another process. See
[pull request #976](https://github.com/sysevol-ai/CodeNib/pull/976) for the
method and data, and the [guard guide](../guard.md) for setup and limits.
