# Source-isolated live Python position queries

Direct definition and reference queries match six saved compiler location sets
for three fixed symbols in CodeNib's complete selected source. This is a
feasibility result for avoiding full graph preparation on positioned queries;
the first cold cross-file fixture still misses references, and no product
routing or comparative coding benefit is established.

The [terminal packet](codegraph_native_source_queries_2026_10_31.json) retains
208 exact text files in fourteen bounded parts, including the first failure,
prospective protocols, original replies, source identities and executed
controls. No model question or provider network request runs.

## Source and execution boundary

The experiment reuses the installed production `LSPClient` with basedpyright
1.39.8. Its developer wheel matches all 485 current Python files and the
retained native extension; it is the admitted assembly from the
[SCIP scanner control](codegraph_scip_text_scan.md), not a CI-produced or
published candidate. Product Python navigation remains on the existing graph
path. No evaluation-only provider is promoted.

An independent checkout of `8639802df6a6d3ba6f118c7a1a1aba535404bab4`
supplies every selected regular source file: 2,390 files, including 1,172
Python files, tests and configuration. The materializer uses retained v2
source authorities and checks every relative path, byte length and SHA-256
before admitting the copied snapshot. Generation one's original and copied
fingerprints both equal
`sha256-v2:866a487140fa1ecc31d7158c13d3f8112717bff21d697ae847cb0c6afee6f2e2`.
It adds no target-only exclusions. A separate preflight verifies existing
build exclusions and one custom exclusion; a selected source link is rejected
before provider launch. Link support is an open gate.

Only the verified snapshot is mounted as project source, read-only, into an
offline Docker container with two CPUs, 4 GiB and 256 PIDs. The original source
root is absent inside the container. Software inputs are separate read-only
mounts; other inherited image volumes are masked. The prepared image and the
10,282-file/link provider manifest are hash-bound. Every installed session
checks all 485 Python files and the native file outside a source checkout.
This Linux/Docker boundary is experimental, not a portable deployment design.

The publication invariant is that a position result belongs to both the
captured original generation and its exact snapshot. Lock order is original
authority, then snapshot authority; publication occurs after both existing
read-session exit checks succeed. The caller owns the server/container and
closes them before releasing either source authority. An invalidated authority
requires explicit recapture and a new session. No new lock, retained job,
lease, database or backend registry is introduced.

## Exact location checks and the cold failure

The first three-file fixture freezes three reference positions but returns
only the definition, without a timeout or reported error. It terminates as a
failure; later guards are unexecuted in that attempt. A separately frozen
diagnostic repeats that cold omission, then obtains all three positions after
one bounded idle wait and again after requesting symbols from every selected
Python file. The failed attempt is never replaced or rescored. Idle is a
readiness heuristic, not a general proof of reference completeness; no
configuration change or diagnosed provider cause is claimed.

The full-source protocol retains a cold reference response, performs one
bounded idle wait, then queries definitions and references for every fixed
target. It does not prime selected callers or retry until a match. Only after
both live generations finish does the assessor open the pinned same-source
SCIP occurrence sidecar. Results are normalized from UTF-16 positions to
UTF-8 byte columns using exact snapshot bytes, then compared as selected-project
location sets. Raw counts, duplicates, invalid/outside paths and errors remain.

Counts show compiler-expected / live-observed. All six sets agree, with no

This comparison establishes neither full graph parity nor multi-hop static
references, arbitrary-repository coverage, runtime calls or model source-read
credit.

## Source changes and component observations

After the first full-source generation, the controller appends one fixed
comment to its own checkout. The old authority rejects the next query before
RPC dispatch while its server remains alive; actual request counters do not
change. Explicit whole-source recapture and a new server produce valid
generation-two locations. That generation has no fresh compiler artifact and
makes no new compiler-parity claim.

A separate two-generation, three-file fixture renames the target and its
import/call sites, shifts its definition line and puts a non-BMP Unicode
character before the call. Both generations match the prospectively fixed
definition and all three reference positions after the bounded idle step.
The second call's UTF-16 columns 23–37 map to UTF-8 byte columns 25–39. A rename
performed after an actual response but before publication rejects that result;
the next stale query is rejected before dispatch. Both cold responses still
return only one of the three expected references and remain recorded.

In the full-source first generation, capture plus copy takes 1.431s, the LSP
initialize exchange 0.096s and the idle operation 0.804s. Subsequent raw
definition/reference RPCs take 0.000876–0.082422s; observations including both
source guards take 0.168541–0.249410s. These are separate descriptive component
observations with prepared software. The entire Docker/install/import startup
span is not timed, so their sum is not a measured first-query latency. No
SCIP-to-live, Serena or complete-task speedup follows from these numbers.

Post-assessment rechecks both full 2,390-file snapshots, the exact single
comment change, every provider-manifest entry and all six owned containers'
independent absence. Earlier model cohorts, scores, denominators and the prior
unexported initial-artifact coverage gap remain unchanged.

## Open product gates

Hold promotion. Before positioned product queries can use this approach,
establish bounded cold completeness, portable source isolation and admitted
project/configuration/dependency closure, with explicit unsupported cases.
Definition/reference primitives do not replace the existing multi-hop graph
contract. No MCP caller, default or source-selection guard changes in this
experiment.

The whole-task quality, at least 20% time improvement, normalized-token and
useful voluntary-call gates remain open. Independent successful confirmations
remain 0/2; external enrollment and repeat use remain 0/5. The reserved
Matplotlib/Django/xarray material stays unopened, with zero new model queries
or API spend.
