# Source-payload workflow results

CodeNib has no demonstrated whole-workflow advantage in this prospective
four-arm comparison. All twelve workflows finish, but no alternative passes
the frozen complete-workload eligibility rule. Hold promotion; this is no
successful independent confirmation and does not establish typed-graph value.

The comparison uses the previously reserved Sphinx, Pylint and scikit-learn
cases, five ordered tasks per repository and fifteen tasks per arm. The
[prospective protocol](codegraph_payload_confirmation.md) fixes the installed
merged #931 wheel, prompts, source criteria, original native grading, model,
limits and voluntary tool choice before inference. All 5,294 bound inputs
remain byte-identical. Historical model exposure is unknown, and three paired
repositories do not support a population-level quality or timing claim.

## Complete workload

All sixty SDK tasks reach successful terminals. Acceptance additionally
requires correct source claims and citations, preserved read-only source,
the fixed exclusive word limits, and original native repair success. Thirty-one
of 48 explanations and eight of twelve repairs pass. No case, selected test,
word limit, source criterion or denominator changes after inference.

Observed time includes product installation, initialization, both SDK clients,
all five task phases, source changes, updates and disconnect. Common project
dependencies and private grading stay separately recorded. Penalty-adjusted
time adds each rejected task's unused deadline allowance; it does not convert
an incomplete answer into a fast accepted result. The full
[assessment](codegraph_payload_assessment_2026_10_30.json) retains every
workflow, task, usage counter, rejection and original native receipt hash.

Eligibility requires fifteen accepted tasks, three native passes and no
material source error across an alternative's complete workload. None meets
that rule, so there is no qualifying comparator for the primary endpoint.
The required quality parity, 20% complete-time improvement and at most 10%
normalized-token regression are not demonstrated. Neither an eligible subset
nor a different grading rule is substituted.

Descriptively, CodeNib takes 32.2% more observed time and 21.0% more normalized
tokens than Native. Against Serena it takes 10.7% more time and 0.7% more
tokens, with the same accepted-task count. These are three-repository
observations with different error outcomes, not causal efficiency estimates.
CodeNib's lower serious-error count is also an observation, not an established
quality advantage.

## What passed and failed

Original native grading executes all 596 selected outcomes: 45 per Sphinx
repair, 18 per Pylint repair and 86 per scikit-learn repair. Every arm passes
Sphinx and scikit-learn. Every Pylint repair fails the original
`test_set_duplicate_lines_to_zero`: the duplicate detector yields no matches,
but the standalone command still prints its `TOTAL` summary where the test
requires empty stdout. There are no collection errors, missing selected
executions or model/native test-patch conflicts. All original failures remain.

Source review checks every mandatory criterion and all material final claims
against the captured original source, or each arm's actual repaired/helper
version after editing. One unblinded maintainer-agent performs this review;
there is no independent adjudication. The explicit judgments, exact version
hashes and source witnesses are retained separately for
[Sphinx](codegraph_payload_assessment_sphinx_2026_10_30.json),
[Pylint](codegraph_payload_assessment_pylint_2026_10_30.json) and
[scikit-learn](codegraph_payload_assessment_sklearn_2026_10_30.json).

Thirty-six explanations satisfy the semantic source criteria; 31 satisfy all
acceptance gates. Six answers exceed the unchanged word limits, including one
that also fails source review. All 48 read-only tasks preserve source.
Material errors include treating a returned translation function as its proxy
result, promising that unguarded file-open errors are caught, calling a
non-pure-module path an early return when AST walking continues, recommending
a bare `return` in a function whose callers require a list, and offering an
empty sparse matrix with the wrong shared classifier row count. CodeNib's
scikit-learn flow also incorrectly accepts arbitrary other string gamma
values. Correct preferred alternatives and passing portions remain visible;
they do not erase incorrect extra advice.

Two local source-derived counterexamples verify the Sphinx and Pylint findings
without model inference or changes to grading. Claimed model-side probes and
test runs are checked against their original recorded replies, including
initial failed probes. Commands are not rerun to replace historical output.
These checks provide source assessment, not solver-read credit.

## Actual use and cost

All eighteen optional product/client connections report connected, with the
native tool inventory available. Recorded optional MCP attempts are Native 0,
Serena 0, Codegraph 6 and CodeNib 0; Codegraph makes two per repository. A
bounded literal command audit finds no additional direct product CLI/API
candidate. That lexical audit is not proof against every possible invocation.
Connection success does not establish intrinsic graph quality or historical
HTTP tool-schema visibility. CodeNib's preparation probes are BM25-only, and
no runtime benefit can be attributed to its graph or source-payload change
when the product is not called.

CodeNib's optional setup totals 24.168 seconds versus Native's 0.020 and
Serena's 12.135. Setup accounts for only 24.148 seconds of the observed
179.861-second CodeNib/Native gap. Removing it in an arithmetic scenario would
still not deliver the target advantage; no model phase is rerun. Remaining
time includes SDK/session work and model task behavior. Metadata exposure,
provider latency and answer length have no identified causal contribution in
this comparison.

The 24 clients record 8,821,055 normalized tokens and $9.311356 in final
cumulative SDK estimates, including main and auxiliary models once. Effective
main model/medium effort and included-plan events are verified; no API-key or
account/provider fallback is used. Invoice charges and complete HTTP request
counts remain unknown. Earlier unknown usage stays unknown; the combined
recorded estimate lower bound is $44.4223508 plus that unknown usage. This is
not a statement of billed spend against the authorized $500 ceiling.

## Decision and retained evidence

Keep CodeNib's source-current navigation and explicit graph requests within
their existing scope. Do not promote a general speed, recall, quality or
default-agent advantage from this result. Startup reduction and complete
source windows are implemented and verified, but useful voluntary graph use
and complete-workflow benefit remain open. The next candidate needs an actual
source-linked cross-file decision where its bounded evidence is useful; a
forced call or another answer to an exposed question cannot establish that.

The fixed Matplotlib/Django/xarray set remains unopened. It cannot supply a
second success until a candidate and its protocol are frozen prospectively;
this set supplies zero success confirmations. External enrollment, consent
and one-week voluntary reuse remain 0/5, with no outreach authorized. Public
package 0.2.4 is unchanged. [Adoption A0](../adoption_roadmap.md) and
[#874](https://github.com/sysevol-ai/CodeNib/issues/874) remain active.

The [results manifest](codegraph_payload_results_2026_10_30.json) reconstructs
535 original output records from 22 bounded parts, separately from the
unchanged 536-record prospective packet. It retains all original model traces,
captured repair patches, native receipts, 48 source judgments, analysis code
and local source counterexamples. Private original grading/test material
remains local with hashes; no reference patch or feedback entered a model.
Independent reconstruction verifies every published byte and hash, all 5,294
frozen inputs and absence of all ninety named current/retained containers.
No ContextBench score or inferred source-read credit is produced.
