# Source-first development comparison

This prospective round tests whether verified source retrieval before full graph
preparation helps a complete coding workflow. It compares Native, Serena,
colbymchenry/codegraph and merged CodeNib #920 on the same fifteen tasks and
fixed project environments. It records development evidence, not either
independent success confirmation.

The Astropy, SymPy and Seaborn members remain those selected from metadata in
[#919](https://github.com/sysevol-ai/CodeNib/pull/919). Their subsequent operator
failures informed #920. Keep every selected case and earlier negative result;
the reserved set remains unopened. Original native grading and the permanently
stopped task-fit round remain unchanged. Historical model pretraining exposure
is unknown.

## Fixed work and comparison

Each repository has five ordered tasks: implementation lookup, cross-file
flow, change impact with two existing tests, repair of the original public
issue, and review after a controlled source addition. Lookup starts a fresh
client; a second client handles the other four tasks on the same workspace.
The captured repair patch is fixed before the controlled addition. All sixty
model task attempts finish or stop under the rules below before private native
grading begins. Missing attempts remain in the denominator.

All conditions retain native Read/Grep/Glob/Bash/Edit/Write tools. Optional
product calls are voluntary. The same upfront-tool settings apply to each
optional product; actual SDK inventory and delivered results are recorded.
Producer flags do not prove native HTTP schema visibility. Source reads and
edits use one arm-owned checkout through the existing authenticated result-file
bridge, with no other arm, grading directory, SDK home or Docker socket in the
target. Network access permits declared tool/project dependency preparation;
this is a source-access policy, not OS network isolation.

The primary endpoint stays complete five-task workflow wall time: start before
product installation and stop after the final SDK disconnect. Include actual
installation, connection, graph preparation, queries, explicit updates,
failures and retries. Common machine/project prerequisites and private grading
are separate recorded costs. This is not an uncached-machine benchmark. Retain
observed time and the predeclared remaining-deadline penalty for omitted work;
a partial workflow cannot be a zero-cost winner.

Keep the existing strict decision: correctness parity, no additional serious
error, at least 20% lower complete time against the strongest complete eligible
alternative, and no more than 10% normalized model-usage regression. An eligible
alternative must have accepted tasks/native repairs and no material source
error for the full workload. If none qualifies, report insufficient evidence.
Do not change eligibility or select a favorable subset after results. Three
repository pairs supply development observations; tasks within a repository
are correlated. Both disjoint independent confirmations remain required.
