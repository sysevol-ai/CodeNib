# Compact pre-load: context management beats retrieval sophistication

## Summary

For agentic code localization, the realizable win is **context management, not
retrieval sophistication**. A pre-load agent that reads 1–2 ranked candidates,
**anchors, then collapses** the bulky candidate dump + exploration trace into a
short distilled seed (`eager_compact`) matches a plain grep agent's accuracy at
**10–40 % lower token cost** — across four models (Qwen3.5-4B/9B/27B, Claude
Haiku 4.5) and two datasets (base + synthesis, 500 queries). Meanwhile, throwing
a **better retriever** at the agent — a 4× larger / code-specialized embedding,
or graph-scoped expansion — does **not** improve its accuracy: the agent's grep
fallback already compensates, so the ceiling is the agent's own navigation, not
retrieval recall.

> Numbers below are regenerated by
> [`scripts/agent_compile/aggregate_compact_results.py`](https://github.com/sysevol-ai/CodeNib/blob/main/scripts/agent_compile/aggregate_compact_results.py).
> Metric = span-overlap recall (`files@k`, `answer_blocks@k`); `symbol@k` is a
> string-match artifact (≈0, agents emit free-form prose). Deltas carry a paired
> bootstrap 95 % CI; `*` = CI excludes 0 (significant).

## Setup

- **Models**: Qwen3.5-4B/9B/27B on local vLLM (`qwen3_xml` tool parser); Claude
  Haiku 4.5 on Vertex.
- **Datasets**: `codenib_base` (100 multi-language instances) and
  `codenib-synthesis` (500 = 100/language × Python/Go/Rust/TS/C++).
- **Arms**:
  - `grep_only` — plain agent, filesystem tools only (baseline).
  - `preinj_eager` — pre-load ranked candidates, "trust the top hits, read 1–2,
    answer, STOP".
  - `preinj_eager_compact` — as eager, but after the first read **collapse** the
    context to `[system, clean_query + judged direction]`, dropping the candidate
    dump and exploration trace (`AgentRunner(compact_after_read=True)`).
- **Seed-richness router** (`compact_keep_reads`): weak models (≤7B) keep the
  last read inline in the seed to avoid re-reading; strong models use the terse
  seed. Set per model size in `harness.py`.

## Results

### 1. Base compact (multi-language, 100 instances/model)

| model | arm | files@5 | blk@5 | token | turns |
|---|---|---|---|---|---|
| 4B | grep | 0.740 | 0.380 | 171 995 | 14.3 |
| 4B | eager | 0.705 | 0.365 | 136 207 | 10.8 |
| 4B | **compact** | 0.717 | 0.377 | 143 751 | 12.4 |
| 9B | grep | 0.751 | 0.502 | 191 218 | 13.5 |
| 9B | eager | 0.796 | 0.553 | 181 395 | 11.4 |
| 9B | **compact** | 0.783 | 0.502 | 152 436 | 11.4 |
| 27B | grep | 0.796 | 0.523 | 169 533 | 12.8 |
| 27B | eager | 0.796 | 0.507 | 135 752 | 10.4 |
| 27B | **compact** | 0.787 | 0.524 | 123 295 | 10.7 |
| Haiku | grep | 0.848 | 0.652 | 178 824 | 14.5 |
| Haiku | eager | 0.822 | 0.579 | 155 203 | 12.7 |
| Haiku | **compact** | 0.840 | 0.613 | 138 305 | 11.6 |

compact − grep accuracy deltas all have CI crossing 0 (iso-accuracy); **token
saving is significant on every model**: 4B −28k*, 9B −37k*, 27B −46k*,
Haiku −41k* (−16 %…−26 %).

### 2. Embedding ablation on the compact agent (Haiku, n=100)

| embedding | retrieval recall@10 | compact files@5 | compact blk@5 | token |
|---|---|---|---|---|
| Qwen3-Embedding-0.6B | 56 % | 0.840 | 0.613 | 138 305 |
| jina-code-embeddings-1.5b | 63 % | 0.812 | 0.614 | 141 178 |
| Qwen3-Embedding-4B | 64 % | 0.825 | 0.604 | 146 707 |

Retrieval recall spans 56–64 % (an 8-pt gap), but the compact agent's span
(blk@5) is flat at ~0.61 — **a better retriever does not help the agent.**

### 3. Seed-richness dial on the weak 4B (the router)

| arm | files@5 | blk@5 | token | turns |
|---|---|---|---|---|
| grep | 0.737 | 0.443 | 168 174 | 13.8 |
| compact keep0 | 0.667 | 0.364 | 141 097 | 12.4 |
| compact keep1 | 0.741 | 0.421 | 138 513 | 10.9 |
| compact keep2 | 0.721 | 0.371 | 138 875 | 11.1 |

keep0 (terse seed) **hurts** the weak model (files@5 0.667 < grep 0.737); keep1
recovers it to grep level (0.741) at −18 % cost; keep2 over-stuffs. → router:
**weak ≤7B → keep1, else keep0.** The router is a *necessity* on weak models.

### 4. Synthesis 500 (5 languages, paired n=500)

| arm | files@5 | blk@5 | token |
|---|---|---|---|
| grep | 0.896 | 0.758 | 154 063 |
| eager | 0.888 | 0.749 | 76 953 |
| **compact** | 0.890 | 0.767 | 94 917 |

compact − grep: files@5 −0.006, blk@5 +0.009 (both CI cross 0 = iso-accuracy),
**token −59k* (−38 %)**. compact − eager: iso-accuracy, +18k* token (on this
*easier* dataset eager already early-stops, so compact's collapse costs a little
more — the compact/eager trade-off flips with task difficulty).

### 5. Retrieval recall@k + latency — flat vs graph-scoped (base n=100)

| embedding | method | @1 | @5 | @10 | @50 | med latency |
|---|---|---|---|---|---|---|
| Qwen3-0.6B | flat | 34 % | 49 % | 56 % | 74 % | 1.3 ms |
| Qwen3-0.6B | scoped (PPR) | 26 % | 33 % | 36 % | 43 % | 10.7 ms |
| Qwen3-0.6B | scoped (BFS) | 9 % | 16 % | 18 % | 32 % | 6.8 ms |
| Qwen3-4B | flat | 37 % | 54 % | 64 % | 83 % | 2.6 ms |
| Qwen3-4B | scoped (PPR) | 28 % | 37 % | 40 % | 46 % | 8.5 ms |
| SweRankEmbed-Large | flat | 42 % | 55 % | 65 % | 83 % | 3.5 ms |
| SweRankEmbed-Large | scoped (PPR) | 28 % | 43 % | 46 % | 59 % | 8.4 ms |
| jina-code-1.5b | flat | 36 % | 53 % | 63 % | 84 % | 1.8 ms |
| jina-code-1.5b | scoped (PPR) | 30 % | 34 % | 38 % | 43 % | 8.4 ms |

`flat` = dense embedding; `scoped` = BM25-seed → graph expansion (GraphRAG), with
PPR (pagerank-ranked) or BFS (`extract_subgraph`, the pipeline default). **Both
graph variants are dominated by flat** — lower recall *and* higher latency. BFS
is faster than PPR (6.8 vs 10.7 ms) but recovers even less (18 % vs 36 % @10):
its k-hop-then-truncate ordering lacks PPR's ranking. jina-code-1.5b is the
retrieval cost/performance sweet spot (1.5B matches 4B's flat recall).

### 6. Graph's value — GraphRAG (search+graph) vs search-only (base n=100)

The `codenib_context` composer (bm25 ⊕ embedding seeds → call-graph expansion)
run as a retriever, with `--no-graph` isolating the graph's contribution:

| k | search-only | search + graph | Δ(graph) |
|---|---|---|---|
| 10 | 49 % | 52 % | +3 % |
| 50 | 49 % | 52 % | +3 % |

Of the 51 search-only misses @10, graph **recovers 3 (6 %), loses 0** (net +3).
So graph adds **marginal, strictly-positive complementary recall** — it recovers
a few structurally-reachable GT (callers / subclasses / elsewhere) that semantic
search misses, and never regresses. But it is small, and (per §2) even an 8-pt
recall gain does not move agent accuracy — so graph is **not an agent lever**.
Its honest home is relational queries (call-graph traversal), not localization.

## Key findings

1. **compact ≈ grep accuracy at 10–40 % lower cost**, across all four models and
   both datasets. This is the robust, realizable win of pre-load.
2. **compact vs eager is difficulty-dependent**: on harder tasks (base) compact
   is cheaper (it cuts the long exploration tail); on easier tasks (synthesis)
   eager already early-stops so compact's collapse costs a little — motivating an
   adaptive gate.
3. **Weak models need the router**: a terse collapse seed hurts the ≤7B model;
   keeping the last read inline (`keep1`) recovers accuracy. The router is
   required, not a nicety.
4. **Retrieval quality does not help the agent** (the central negative): swapping
   the embedding (recall 56→64 %) or using graph-scoped expansion leaves the
   compact agent's span unchanged — the grep fallback compensates, so the ceiling
   is the agent, not retrieval. This subsumes graph / skill-subset / embedding
   scale into one "retrieval sophistication doesn't move agent accuracy" result.

5. **Graph is a dominated / marginal RAG op**: graph-scoped retrieval is
   dominated by flat (lower recall + higher latency, PPR and BFS alike); graph as
   a *complement* (§6) adds only +3 % recall (recovers 6 % of misses, 0
   regressions). Graph's realizable home is relational queries, not localization.
