# Source-first development result and product decision

Hold promotion: the source-first change does not establish CodeNib's required
whole-workflow benefit. CodeNib accepts 8/15 tasks against the best observed
alternative count of 9/15, and receives no optional product call. No alternative
meets the frozen complete-workload eligibility rule, so the result is
**insufficient evidence**, without a selected comparative winner.

The [prospective protocol](codegraph_source_first_protocol.md) fixes fifteen
tasks on Astropy, SymPy and Seaborn, each executed with Native, Serena,
colbymchenry/codegraph and CodeNib. These sources informed merged
[#920](https://github.com/sysevol-ai/CodeNib/pull/920), so this is development
evidence and satisfies neither independent success confirmation. The reserved
set remains unopened. Earlier cohorts and the stopped task-fit round retain
their original outcomes.

## Accepted work and complete costs

All sixty attempts reach successful SDK terminals, and all 48 read-only tasks
preserve source bytes. Exact-version review accepts 23 explanations and rejects
25. Nine of twelve repairs pass the unchanged original native grading. A

Observed time starts before actual product installation and ends after the
final SDK disconnect, including setup, queries and actual test/update work.
Common prepared project prerequisites and private grading stay separate. This
is not an uncached-machine benchmark. Rejected tasks add
`max(0, frozen task deadline - observed task seconds)` to the retained observed
time. No rejected answer or failed repair is omitted or assigned zero cost.

Descriptively, CodeNib's raw time is 2.3% below Native and 25.8% below Serena;
its normalized usage is 4.1% above Native. These differences establish neither
quality parity nor intrinsic retrieval benefit: CodeNib accepts fewer tasks
than the maximum alternative, and both CodeNib and Serena remain unused.
Codegraph's actual 798.795-second Seaborn repair includes the agent's broad
test run and waiting; keep that cost, without attributing it all to retrieval.
The three paired repositories are three clusters, not fifteen independent
observations. No population or statistical-significance claim is made.

The [complete analysis](codegraph_source_first_assessment_2026_10_30.json)
retains each task, original grade, observed time, fixed rejection penalty and
final cumulative usage. All alternatives have failed acceptance conditions;
none is eligible for the frozen 20% improvement test. Selecting a weaker
baseline or removing a word-limit failure afterward would change the protocol.

## What the source and native assessments found

One unblinded maintainer-agent checks all mandatory criteria and material final
claims against the captured source version. There is no independent
adjudication claim. Original source is used before repair; post-edit answers
use each arm's exact repaired source and the controlled helper. Each finding
keeps its original answer quote, source hash and 1-based evidence range.

Thirty-four explanations pass semantic source review. Twenty fail the separate
prospective word limit; nine of those also fail semantic review. Their union
is 25 rejected explanations, leaving 23 accepted. All fourteen semantic failures
are retained even when a word limit already rejects the task. No limit is
waived or retrospectively truncated.

- Astropy: Native and CodeNib describe an unreachable ndarray return guard as
  an operational path after the value has already become a list. CodeNib also
  conflates forward-axis independence with the inverse placeholder being
  harmless. Executing the exact original inverse on a triangular transform
  returns pixel 9 instead of 5 despite forward independence. Its blanket
  absence claim also misses an existing wrapper-construction test; that test
  is not a numerical inverse test.
- SymPy: all four flow answers retain the original imaginary-zero root
  subtraction and its defects. The impact answers miss required signature
  mapping coverage or make false dispatch/control-flow claims: a bare
  ConditionSet uses its own membership method, and the imaginary-zero branch
  continues rather than returning early. Local base-set rebinding does not
  mutate the original ImageSet properties. Two lookup answers also promise a
  ProductSet instance for every base; an empty base canonicalizes to EmptySet.
- Seaborn: Codegraph promises input-length preservation that `Scale.__call__`
  does not enforce; an exact-function witness changes length three to one.
  Native leaves coordinate/legend gating contradictory. Serena and CodeNib
  misstate the returned `base` configuration as `None`; every captured repair
  retains the named default sentinel. Their correct no-immediate-render
  conclusion is preserved alongside that ordinary configuration error.

Detailed decisions are retained for
[Astropy](codegraph_source_first_assessment_astropy.json),
[SymPy](codegraph_source_first_assessment_sympy.json), and
[Seaborn](codegraph_source_first_assessment_seaborn.json). Counterexamples are
retrospective source-adjudication evidence, not new grading tests, model inputs
or inferred solver read credit.

The [source-review correction](codegraph_source_first_review_correction_2026_10_30.json)
retains the initial local 25/48 assessment alongside the corrected 23/48.
Pinned-source execution rejects Codegraph's explicit ProductSet-instance promise
and Serena's one-fold-product promise on an empty base. Native and CodeNib
quote the constructor expression without that additional type guarantee; their
scores stay unchanged. This corrects two source judgments before publication,
with the same criteria and every original model/native outcome preserved.

All 1,352 originally selected native test outcomes actually execute: 41 Astropy,
47 SymPy and 250 Seaborn tests per arm. There are no missing selected executions,
collection errors or model/native test-patch conflicts. Native, Serena and
CodeNib each fail SymPy's original `test_imageset_intersect_real`; Codegraph
passes it. All other selected outcomes pass. These are behavioral failures,
not collection failures. Keep the original tests, parser and grading; the
post-edit explanation's acceptance never repairs an earlier failed native grade.

## Tool use and metadata delivery

All optional products appear connected in the actual SDK initialization, with
their tools in the inventory. Native tools remain available and optional calls
remain voluntary. CodeNib has no MCP call or detected explicit product CLI
invocation across its fifteen tasks; Serena also has no MCP call. Codegraph
has nine attempts. Faster fallback execution cannot establish graph efficacy.

A separate network-disabled pinned CLI/SDK control repeats the original
producer advertisements and inspects decoded outgoing loopback request bodies.
All four tool descriptions and input schemas are unchanged in transmission.
CodeNib's 797-character instructions and Serena's 130-character instructions
are complete. The CLI retains only the first 4,096 of Codegraph's 6,718
instruction characters. These scripted responses make no provider/model call.
This is a transport control, not interception of historical native-subscription
HTTP requests or a causal tool-choice experiment.

Three failed fixture versions remain retained: their replay serialized optional
null annotation fields, which the CLI rejected. The corrected replay omits
those optional null fields and preserves the schemas. These harness failures
are not historical product-delivery failures. SDK-generated configuration and
default prompts are excluded from publication; complete decoded request-body
receipts remain local with hashes.

The next bounded product step is clearer task-facing exploration guidance:
say what source question it answers and how to start with a query, while keeping
explicit relationship requests and their preparation costs visible. Validate
actual delivery and useful voluntary use before another efficacy cohort.
Do not force calls, add unsupported accuracy/speed promises, or repeat these
exposed tasks to seek a positive result.

## Accounting, preservation and open gates

The round records **$10.0645086 in SDK estimates** and 9,461,581 normalized
main/auxiliary tokens, counting each client's final cumulative input,
cache-creation, cache-read and output once. Thinking tokens are not added again.
All latest-query usage is known in this round; earlier interrupted unknown
usage remains unknown. Actual invoices and complete trial HTTP counts remain
unknown. Native included subscription is used without an API/provider/account
fallback; the original $500 API authorization is unchanged.

The [outcome packet](codegraph_source_first_results_2026_10_30.json) losslessly
reconstructs 556 public observation, grading-summary and controller files in
24 parts. Another 187 private native/fixture files are retained by hash. All
4,936 frozen inputs are reverified unchanged; the original protocol packet is
unchanged. Prior shared-launcher drift stays disclosed rather than asserting
that every old live path matches its old seal. All 40 model, native-grading and
metadata-control containers are independently absent. Preserve the first
packaging failure on an excluded SDK configuration file; it changes no outcome.

Hold comparative-efficiency promotion and default-rollout expansion. Keep the
shipping scope at verified source navigation and bounded indexed references
where the provider is ready, with explicit rebuilding and full-graph resource
limits. Source-first admission does not promote complete graph coverage.
Public package 0.2.4 is unchanged.

Both independent whole-task success confirmations remain open. External
recruitment, consent and seven-day reuse remain **0/5**; no outreach is
authorized. The complete objective in [adoption A0](../adoption_roadmap.md)
and [#874](https://github.com/sysevol-ai/CodeNib/issues/874) remains active.
