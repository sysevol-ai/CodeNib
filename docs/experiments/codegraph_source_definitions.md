An exact positional definition query can now use captured Python source before
building a complete graph. Local installed-MCP controls pass on the generated
fixture and complete CodeNib source. This establishes a bounded navigation
path; comparative coding benefit remains unproved and references still have
an open physical-call coverage gate.

checks, not new model tasks, timing comparisons or independent confirmations.
The packet reconstructs 365 exact records in seven bounded parts, with 25

## Admitted behavior

The current consumer is `lsp_definition` on a verified local Python-only
manifest with deferred graph preparation and the full tool surface. The
worker receives every selected file from the retained source authority,
including opaque assets, and prepares every selected Python/stub file. It
runs the pinned browser-basedpyright 1.39.8 bundle with the previously verified
software-only typeshed path relocation. The bundle is authenticated by its
full SHA-256 hash; Node `vm` is not a security sandbox.

Only a single standard go-to-definition location that exactly matches a
captured function or class name token can be returned. Python input columns
are zero-based UTF-8 byte offsets, converted strictly to the worker's UTF-16
positions. Output locations use 1-based lines and identify
`captured_python_definition_candidate_v1`. The source must still be read before
describing behavior. One declaration candidate does not prove a unique runtime
call target. No private analyzer type or flow query is used.

Multiple, external, missing or unsupported targets close the worker and use
the existing complete-graph preparation. References, routes and symbol lookups
retain that route. Runtime selection never downloads software; the explicit
LSP installer prepares both pinned Python packages. Graph-only installation
keeps its ordinary-server recipe. A custom Python server selection, Windows,
mixed languages, artifacts and the explore-only surface retain their existing
behavior. Public 0.2.4 is unchanged.

## References remain an open gate

The original frozen complete-graph fallback finds ten of eleven expected positive fixture call
lines, misses a wildcard-import call and includes one post-rebinding call from
the five negative cases. The prior installed version returns identical node
fields from the exact same graph artifact. This does not establish compiler
parity or improve the earlier strict call-identity oracle.

The existing Python identity layer deliberately retains possible declarations
sharing a lexical binding. Such static reference candidates are not physical
runtime call identities. Preserve that contract and the failed call gate;
neither silent filtering nor changing the oracle would prove improved
correctness. The separate [wildcard repair](codegraph_python_wildcard.md)
now finds 11/11 positive lines in its own admitted compiler/MCP control; the
remaining raw-compiler alias-binding error stays distinct from intentional
lexical unions. Neither result changes the old packet. Combined runtime and
representative semantic/configuration coverage remain required. The earlier failed function-type/flow controls
and frozen 400-query diagnostic are unchanged.

## Ownership and product decision

The MCP context lock precedes its query lock and bounded worker I/O. Source
leases cover export, while original-source verification brackets analysis;
publication linearizes at the enclosing query's final successful source check.
The worker exits and its pipes and payload close before graph preparation or
intentional release of usable source. Authentication failure immediately
revokes source authority; the failed indexed query then reaps its immutable
worker before returning. Failed cleanup keeps the process owner reachable,
marks the worker unavailable and attaches retry ownership to the source error.
Source revocation must never wait on a worker. Session teardown cannot
close a newer connection's worker. The deterministic regression tests and real
installed stopped-worker control exercise these boundaries.

Keep promotion on hold. This component does not make the default exploration
workflow avoid graph preparation, prove a 20% complete-task improvement or
establish voluntary use. Independent successes remain 0/2; consenting external
users and seven-day reuse remain 0/5. No model inference, account fallback or
new spend is added. A0 and issue #874 remain active.
