# Common runtime and source-update admission

All four arms can install and answer the selected source lookup in each of the
three pinned repositories. Native tools, Serena and CodeNib also return the
new helper's current source in the original connection; CodeNib requires an
explicit rebuild. Codegraph's immediate query reports pending synchronization.
Separate controls retain that reply, wait one second and succeed on one
identical retry in the same connection.

These are model-free preparation controls. Each arm receives an explicit
definition target, and native tools read a known source span. They do not
measure discovery, whole-task benefit, answer correctness or voluntary tool
choice. The [archive](codegraph_common_runtime_2026_10_28.json) retains seventeen
workflow controls, including all five failed outcomes, plus packaging and
runtime-identity diagnostics. The original model cohorts are unchanged.

## Matching project and product environments

Each repository uses its pinned neutral arm64 image and one-commit source
snapshot from the original pilot. The same source/project preparation precedes
each arm's product-installation clock. Package metadata confirms that all four
arms have identical target Python versions and installed project dependencies
within each repository. The neutral Requests image has an empty `/testbed`
and none of the optional product CLIs installed.

The selected source remains Requests `3c88e520`, Flask `7ee9ceb7` and pytest
`8aba863a`. Target/test environments come from their original pinned native
harness images; product tools use the common Python `3.13.18`, Node `22.23.1`
and native Claude CLI prerequisites. Source copies and common project
installation are recorded separately from arm-specific product installation.

| Arm | Actual product and provider identity |

| Serena | `serena-agent 2.1.0`, Pyright `1.1.403`, MCP `2.2.0`, `claude-code` context and v2 REPL |

All three installed environments for a selected product have identical package
identities. CodeNib is a newly built, hash-bound source candidate, not the
published PyPI 0.2.4 wheel. Its 484 Python files match the pinned source, and its
workspace-owner ABI extension is included. No product release is made.

## Installation and update costs

These observed seconds start from the pinned neutral machine/project
environment. Arm-specific package installation, provider preparation,
initialization and registration are included. Machine/runtime provisioning,
source copying, common project preparation and candidate packaging are
separate. Cache/network conditions and exact commands remain in the archive;
these numbers do not represent an uncached machine setup or task-time ratio.

| Arm | Requests install/init | Flask install/init | pytest install/init |
| --- | ---: | ---: | ---: |
| Native | No additional product | No additional product | No additional product |
| Serena | 3.607 | 3.746 | 3.891 |
| Codegraph | 6.081 | 5.979 | 8.622 |
| CodeNib | 21.372 | 20.919 | 36.177 |

Serena explicitly selects Python during project creation and prepares cached
Pyright before entering the network-disabled runtime. `UV_OFFLINE=1` prevents
its uv launcher from attempting a registry lookup there. Eager full-project
indexing is not required by this startup path.

The original controlled source additions are identical in every arm. Each
selected initial body and added helper body is checked against its file hash,
source version and reported coordinates. All original tracked files and Git
HEADs remain unchanged; generated project metadata and the known added helper
remain visible in the recorded Git status.

CodeNib's current-source guard rejects the first query after the addition with
visible rebuild instructions. The controller executes the ordinary CLI, then
queries the new graph root and source body in the same MCP connection. The
captured replies include the new helper's reference to its expected production
factory; the archive verifies that relationship separately after execution.
The complete CLI rebuild commands take 12.618, 12.605 and 27.364 seconds for Requests,
Flask and pytest. They include CLI/registration work and are not isolated
compiler timings. The controller explicitly chooses the rebuild; this is not
an observation of spontaneous agent recovery.

Codegraph's three immediate post-addition replies explicitly warn of pending
synchronization and omit the new helper body. Those controls stay failed. A
separate recovery rule is written before its controls execute: only an explicit
pending-sync reply permits a one-second wait and at most one identical retry.
All three recovery controls return the complete current helper body in the
original MCP connection. The retained first replies, wait and second queries
are part of their costs. A one-second waiting condition does not measure the
watcher's exact update latency or resolve other source-selection omissions.

## Retained preparation and audit failures

The two earlier pytest/CodeNib developer controls fail in the controller. One
committed Docker image retains the active bind path in `Config.Volumes`, causing
a duplicate mount when that same path is also masked. The other incorrectly
requires the literal word `stale` in an otherwise correct source-change error.
Both original failures, costs, replies and controller versions are preserved.
The fixed twelve-arm/source batch and three bounded Codegraph follow-ups are
separate controls, not replacements or rescored model results.

The first host wheel builds without its optional native extension; its
configured Python development header is absent. It is excluded from every workflow.
The selected wheel is rebuilt in an owned complete Python tool runtime; both
packaging receipts remain archived.

Runtime auditing also retains six failed diagnostic requests: three assume an
unused Codegraph installation directory, and three test strict workspace
provisioning rather than the existing-checkout graph path. The latter correctly
reject unavailable `kcmp` permissions under the ordinary container profile.
Corrected identity-only requests read the actual installed npm package tree and
CodeNib package/provider identities. They establish identity and the imported
owner ABI, not strict-workspace capability support. No container permissions or
product safeguards are weakened.

## Preservation and next gate

Every container creation records its returned identity before startup or
verification. Only that invocation's identities are removed after owner-label
checks. All fifty-one workflow, packaging and audit containers are confirmed
absent. No credential/profile, Docker socket, other arm or grading material is
mounted into a workflow; source-query stages have networking disabled. Actual
resource limits are retained. All seventy-six earlier tracked CodeGraph JSON
artifacts remain byte-identical to baseline `733343e8`.

Complete source-checking of the full corrected rubric and freeze a separate
complete model/tool/time/resource protocol before another inference cohort.
Retain installation and update costs, pending/unavailable results, native
fallback, automatic optional-tool choice and unused tools. These controls add
no model inference and enroll no external users. Broader provider coverage,
representative workflows beyond this source addition, automatic rebuilding,
the 20% benefit gate and five-user week-long reuse remain open under
[#874](https://github.com/sysevol-ai/CodeNib/issues/874).
