# Function types do not establish a unique source target

An exposed-source function-reference prototype now finds all eleven required
calls in the existing generated fixture and excludes all five negative calls.
It still does not qualify for product routing: a conditional reassignment can
collapse distinct functions to one type, and the conservative control-flow
guard also rejects a required query on the complete CodeNib source.

The [terminal packet](codegraph_python_function_flow_2026_10_31.json) preserves
the capability observation, both failed controls, a focused harness correction
and their original deliveries. These are development diagnostics, not new
coding tasks, independent confirmations or replacements for previous results.

## Resolution and its counterexample

The unchanged browser-basedpyright 1.39.8 bundle runs against complete captured
source in its virtual filesystem. The existing software-only typeshed path
relocation remains byte exact. No dependency, installed provider, product
route or MCP default changes. Node `vm` is not a security sandbox.

Seven already exposed positions compare ordinary definition replies with the
pinned analyzer's private `getTypeOfExpression` result. Ordinary definitions
return both the original function and a later assignment. Before that
assignment, a complete function type retains the original function declaration;
after it, the type retains the replacement declaration. The wrapper follows
only real import-alias tokens and admits locations with an exact captured
function declaration. Incomplete, unknown, non-function and overloaded types
cannot establish a complete result.

This distinction is insufficient after a control-flow join. In a separate
generated function, a flag conditionally replaces an imported function before
the final call. Both targets have the same callable shape. The analyzer reports
one complete function type and the replacement declaration, so the first
wrapper incorrectly excludes a possible original-function call while marking
its result complete. Preserve this failed gate. The upstream
[function-type comparison](https://github.com/DetachHead/basedpyright/blob/v1.39.8/packages/pyright-internal/src/analyzer/types.ts)
compares callable structure; a retained declaration is not a uniqueness proof.
Executing the same exposed generated function returns 3 with a false flag and
1 with a true flag, confirming both runtime targets. That separate witness
preserves source bytes and does not change the original control's grade.

A separately frozen guard follows the analyzer's own
[control-flow nodes](https://github.com/DetachHead/basedpyright/blob/v1.39.8/packages/pyright-internal/src/analyzer/codeFlowTypes.ts).
It accepts only a bounded single chain of supported assignment, annotation,
call and wildcard-import nodes ending at an entry node. Branches, loops,
unsupported gates, missing flow and exhausted traversal remain unsupported.
It neither reconstructs Python control flow nor claims runtime call tracing.
The conditional call now remains partial, while the earlier definite call
survives. However, an unrelated preceding branch also prevents the guard from
admitting the required full-source origin. This conservative failure is an
open coverage gate, not permission to silently return a complete empty result.

The original fixture's recapture renamed the original function but also
imported `other.target_new` without renaming `other.target`. Its original
partial outcome remains intact. Only the second control's separate fixture
corrects that import to the existing replacement function. Both controls retain
the same eleven positive and five negative requirements, source rename, line
shift and Unicode checks. Neither revises the two earlier 10/11 controls or
the frozen 400-query comparison.

## Product decision

Keep the function-flow wrapper experimental. A complete callable type cannot
by itself authorize physical-source credit; the current conservative guard
also fails representative coverage. Actual MCP position routing still prepares
the existing graph. A product route needs a narrower proven flow boundary or
an explicit source-current graph fallback, with its real preparation cost
included, plus representative configuration/dependency and installed-runtime
acceptance. This turn does not install a private-API provider or bypass the
existing source-selection guard.
